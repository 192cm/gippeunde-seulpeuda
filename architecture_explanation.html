화면 흐름

앱은 Navigation Compose보다는 Android Activity 전환을 중심으로 흐릅니다. 화면 내부 UI는 Jetpack Compose로 작성되어 있습니다.

1. MainActivity

그룹을 선택하고 오늘의 감정 목표를 생성합니다. 미션, 피드, 아카이브로 이동하는 허브입니다.

2. MissionActivity

카메라/갤러리/프리셋으로 이미지를 준비하고 얼굴이 정확히 1명인지 검사합니다.

3. FaceAndEmotionAnalyzer

ML Kit으로 얼굴 수를 확인하고 TFLite 모델로 7개 감정 확률 벡터를 계산합니다.

4. ResultActivity

목표 감정과 결과 감정의 거리를 점수로 바꾸고, 위치 정보를 붙여 저장합니다.

5. Group/Archive

그룹 피드, 랭킹, 슬라이드쇼에서 저장된 제출 결과를 다시 보여줍니다.

핵심 흐름은 “목표 생성 → 사진 입력 → 얼굴 검증 → 감정 추론 → 점수 계산 → 저장 및 공유”입니다.

계층별 아키텍처

Presentation

MainActivity, MissionActivity, ResultActivity, GroupActivity, ArchiveActivity가 화면 단위 진입점입니다.

각 Activity는 setContent로 Compose 화면을 렌더링합니다.

Domain Logic

FaceAndEmotionAnalyzer가 감정 추론, 얼굴 수 검증, 점수 계산을 담당합니다.

점수는 7차원 감정 벡터 사이의 유클리드 거리를 이용해 (1 - distance) * 100으로 계산합니다.

Local Data

MissionRecord, MissionRecordDao, AppDatabase, MissionRepository가 Room 기반 개인 미션 기록을 저장합니다.

날짜, 사진 경로, 목표 감정 JSON, 결과 감정 JSON, 점수, 위도/경도를 보관합니다.

Mock Remote

FirebaseRemoteMock는 실제 Firebase 대신 SharedPreferences와 Moshi로 그룹, 초대 코드, 피드 데이터를 저장합니다.

그래서 네트워크나 Firebase 설정 없이도 피드/랭킹 기능을 시연할 수 있습니다.

Model Training

training/train_mobilenetv2_fer2013.py가 FER2013 데이터셋을 학습해 .tflite 모델과 라벨 파일을 만듭니다.

완성된 파일은 app/src/main/assets에 복사되어 Android 앱에서 로드됩니다.

데이터 흐름 자세히 보기

MainActivity └─ FirebaseRemoteMock.getGroupTargetEmotion(groupId, today) └─ 목표 감정 Map<String, Float> 생성 MissionActivity ├─ 카메라/갤러리/프리셋으로 Bitmap 준비 ├─ FaceAndEmotionAnalyzer.detectFaces(bitmap) │ └─ ML Kit Face Detection 결과가 1명이어야 통과 └─ FaceAndEmotionAnalyzer.analyzeEmotion(bitmap, context) └─ emotion_mobilenetv2.tflite 실행 후 7개 감정 확률 반환 ResultActivity ├─ FaceAndEmotionAnalyzer.calculateScore(target, result) ├─ MissionRepository.insert(MissionRecord) │ └─ Room DB에 개인 기록 저장 └─ FirebaseRemoteMock.addFeed(FeedMock) └─ SharedPreferences에 그룹 피드 저장 GroupActivity / ArchiveActivity └─ 저장된 FeedMock 목록을 읽어 피드, 랭킹, 슬라이드쇼 표시

주요 파일 역할

파일 역할 조교님께 설명할 포인트
MainActivity.kt 앱의 시작 화면과 그룹 선택, 오늘 미션 진입 그룹 ID와 날짜를 seed처럼 사용해 매일 다른 목표 감정 조합을 만듭니다.
MissionActivity.kt 사진 입력, 프리셋 테스트, 얼굴 수 검증, 분석 시작 실기 시연이 쉬우도록 카메라뿐 아니라 갤러리와 mock 프리셋도 제공합니다.
FaceAndEmotionAnalyzer.kt ML Kit 얼굴 검출, TFLite 감정 추론, 점수 계산 AI 추론을 서버로 보내지 않고 기기 내부에서 처리하는 구조입니다.
ResultActivity.kt 결과 확인, 위치 태그 선택, Room/피드 저장 한 번의 제출이 개인 기록과 그룹 피드 양쪽에 반영됩니다.
FirebaseRemoteMock.kt 그룹, 초대 코드, 피드 mock 저장소 이름은 Firebase지만 현재 구현은 로컬 mock이라 Firebase 계정 없이 평가 가능합니다.
MissionRecord*.kt Room Entity, DAO, Repository 개인 제출 기록은 앱 내부 DB에 남기므로 아카이브/완료 여부 판단에 사용할 수 있습니다.
training/ 감정 분류 모델 학습 파이프라인 Android에 들어간 모델 파일이 어디서 왔는지 설명할 수 있는 별도 학습 구조입니다.

AI/ML 처리 구조

얼굴 검증

ML Kit Face Detection을 사용해 사진에 얼굴이 몇 명 있는지 확인합니다.

미션 제출 조건은 “정확히 한 명”입니다.

감정 추론

emotion_mobilenetv2.tflite를 로드해 96x96 RGB 입력으로 추론합니다.

출력은 7개 감정 라벨의 확률 분포입니다.

점수 계산

목표 벡터와 결과 벡터의 거리를 계산해 0점에서 100점 사이로 변환합니다.

가까울수록 높은 점수입니다.

여기서 중요한 점은 얼굴 검출과 감정 분류가 역할이 다르다는 것입니다. ML Kit은 “제출 가능한 사진인지”를 판단하고, TFLite는 “감정이 목표와 얼마나 맞는지”를 판단합니다.

저장 구조

Room DB: 개인 기록

mission_records 테이블에 제출 날짜, 사진 경로, 감정 JSON, 점수, 위치 좌표가 저장됩니다.

앱이 오늘 이미 제출했는지 확인하거나, 개인 기록을 다시 보여줄 때 사용하기 좋습니다.

SharedPreferences Mock: 그룹 피드

FirebaseRemoteMock가 그룹 목록과 피드 목록을 JSON 문자열로 저장합니다.

실제 원격 DB를 붙이기 전에도 그룹 시연이 가능하도록 만든 임시 백엔드입니다.

빌드와 의존성

Android 빌드는 Kotlin DSL 기반입니다. 버전은 gradle/libs.versions.toml에서 중앙 관리하고, 앱 설정과 의존성은 app/build.gradle.kts에 모여 있습니다.

발표용 설명 스크립트

“저희 프로젝트는 Android Compose 기반 감정 미션 앱입니다. 시작 화면에서 사용자는 그룹을 고르고, 앱은 그룹 ID와 날짜를 이용해서 오늘의 목표 감정 벡터를 만듭니다. 사용자가 셀피를 찍거나 갤러리 사진을 고르면 먼저 ML Kit으로 얼굴이 정확히 한 명인지 검사합니다. 그 다음 TensorFlow Lite 모델이 사진을 7개 감정 확률로 분류하고, 목표 감정과 결과 감정의 거리를 계산해 점수로 보여줍니다.

저장은 두 갈래입니다. 개인 제출 기록은 Room 데이터베이스에 저장하고, 그룹 피드와 랭킹은 현재 Firebase를 대신하는 로컬 mock 저장소에 저장합니다. 그래서 실제 서버 없이도 전체 플로우를 시연할 수 있고, 나중에 Firebase로 교체하기도 쉽습니다. 별도의 training 폴더에는 FER2013 데이터셋으로 MobileNetV2 모델을 학습하고 TFLite 파일로 export하는 파이프라인이 있어서, 앱의 AI 모델이 어떤 방식으로 준비되는지도 함께 설명할 수 있습니다.”

Firebase 이름

FirebaseRemoteMock는 실제 Firebase 연결이 아니라 mock입니다. 발표 때 “원격 기능을 흉내내는 로컬 저장소”라고 말하면 정확합니다.

위치 기능

의존성에는 Google Play Services Location이 있지만, 결과 화면은 주로 캠퍼스 hotspot 선택 방식으로 위치 태그를 붙입니다.
